Architecture

Five small C files. One I/O thread, one UI thread. No third-party runtime dependencies.

Modules

FileResponsibilityKey API
src/main.c Entry point, arg parsing, CLI/GUI dispatch, console attach wmain, run_cli
src/http.c WinHTTP download into a malloc'd buffer with progress callback http_get
src/unzip.c miniz wrapper: extract zip-in-memory to a directory; path-traversal guard unzip_buffer
src/gui.c Win32 window, progress bar, folder picker, worker thread, completion UX gui_run
src/embed.c EMBEDDED only — exposes the C23 #embed'd zip bytes zbs_zip_data, zbs_zip_size

Threading model (GUI)

  • UI thread owns all window handles; never blocks.
  • Start creates one worker thread (CreateThread) running download → extract.
  • Worker communicates back via PostMessageW only — no shared mutable state:
    • WM_APP+1 — progress percentage in wParam
    • WM_APP+2 — strdup'd status text in lParam
    • WM_APP+3 — completion; wParam = return code
  • On WM_APP+3 the UI updates a STATE_DONE_OK / _ERR flag and either relabels Start → Close or re-enables for retry.

Security notes

  • unzip_buffer rejects entries with absolute paths, drive letters, or any .. component before opening any file (path_is_safe in src/unzip.c).
  • HTTPS is enforced when the URL is https://; certificate validation is delegated to Schannel via WinHTTP defaults.
  • Manifest sets requestedExecutionLevel = asInvoker — no UAC prompt.
  • Manifest's activeCodePage = UTF-8 ensures any narrow-API path handling round-trips Unicode filenames cleanly.

Manifest & resources

res/wistribute.rc embeds res/wistribute.manifest as resource type 24, ID 1 — the Win32 application-manifest convention. Effects:

  • Common Controls v6 → themed (XP-style) progress bar
  • UTF-8 active code page
  • Marked compatible with Windows 8.1 / 10 / 11
