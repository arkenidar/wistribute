wistribute Overview Build Usage Architecture Plans

Build

Two parallel build systems — CMake (primary) and GNU Make (mirror). Both produce identical binaries, both auto-fetch miniz and the embedded payload zip at configure/build time.

Prerequisites

  • Windows x64 (native or Wine), or any mingw-w64 cross toolchain
  • mingw-w64 GCC — ≥ 15 for C23 #embed; older GCC (e.g. 14) is fine and uses the generated-array fallback
  • xxd (vim-common) when the embedded payload uses the byte-array fallback
  • windres from binutils (manifest compilation)
  • CMake ≥ 3.20 or GNU Make 4.x
  • Network access at first configure (one-shot fetch of miniz + payload)

CMake (recommended)

cmake -S . -B build -G Ninja
cmake --build build

Outputs land in build/wistribute.exe and build/wistribute-offline.exe.

Useful options

OptionDefaultPurpose
WISTRIBUTE_BUILD_DOWNLOADONBuild the download-mode exe
WISTRIBUTE_BUILD_EMBEDDEDONBuild the offline exe (downloads payload at configure time)
ZBS_URLZeroBraneStudio master.zipOverride the embedded source zip URL
MINIZ_TAG3.1.1miniz release tag to vendor
cmake -S . -B build -DWISTRIBUTE_BUILD_EMBEDDED=OFF
cmake -S . -B build -DZBS_URL=https://example.com/your.zip

GNU make (mirror)

Same flags, libs, and vendored deps as the CMake path. Convenient inside an MSYS2 / mingw shell.

make            # builds both
make download   # only wistribute.exe
make embedded   # only wistribute-offline.exe
make clean      # remove build/
make distclean  # remove build/ and payload/

Cross-build for Wine on Debian

No MSYS2 needed — Debian's mingw-w64 cross-compiler builds Win64 exes directly and Wine runs them:

cmake -S . -B build-w64 -G Ninja \
  -DCMAKE_SYSTEM_NAME=Windows \
  -DCMAKE_C_COMPILER=x86_64-w64-mingw32-gcc \
  -DCMAKE_RC_COMPILER=x86_64-w64-mingw32-windres
cmake --build build-w64

Debian packages: gcc-mingw-w64-x86-64-posix, ninja-build, wine, xxd (vim-common), plus network at first configure.

wine build-w64/wistribute-offline.exe --cli --out 'C:\zbs'

Debian's mingw-w64 GCC is 14, which lacks C23 #embed; the build generates the embedded payload as a byte array via xxd -i instead. On GCC ≥ 15 / Clang ≥ 19 the native #embed path is used automatically.

What gets fetched at build time

ArtifactSourceCached at
miniz amalgamation github.com/richgel999/miniz/releases/.../miniz-3.1.1.zip build/_deps/miniz/
Embedded payload github.com/pkulchenko/ZeroBraneStudio/.../master.zip build/_deps/payload/zbs.zip (CMake) or payload/zbs.zip (Make)

Verifying the binary is self-contained

objdump -p build/wistribute.exe | grep -i "DLL Name"

Expected output (only Windows system DLLs):

COMCTL32.dll
GDI32.dll
KERNEL32.dll
msvcrt.dll
ole32.dll
SHELL32.dll
USER32.dll
WINHTTP.dll

The offline exe omits WINHTTP.dll.
